## 后台控制与安装

`ProcessController` 持久化 PREPARING → STARTING → VERIFYING → PROMOTING → OBSERVING → DRAINING → HANDOFF → ACTIVATING → COMPLETED。root CLI 只暂存产物和提交/查询任务；退出 CLI 不影响推进。相同产物重复提交复用任务，有未解决的交接或未退出实例时拒绝第三实例。

配置冻结后从 owner 配置推导 profile。验证统计同时包含执行结果与新版直接入口结果；Card、健康检查和未访问 Agent 的响应不作成功样本。验证期失败或到期缺样本自动回退；全量观察缺直接入口证据时保留两版并进入 RECOVERY_REQUIRED，resume 保留已有证据。源排空超时也保留两版，禁止强行宣布完成。

配置 revision 从权威 owner 读取，修复管理更新后无业务请求时业务缓存滞后造成的候选健康误判。status 读取最近已持久化的不可变报告，交接等待不持有查询所需互斥锁；实际决定、队列与身份另外读取，不承诺所有字段处于一个跨进程原子时刻。

正式 unit 通过初始不可变产物的 `launch` 选版并 exec，不保留 supervisor。读决定后在取得 owner.lock 时再次核对版本；已选产物缺失或摘要/日志损坏时拒绝启动。有业务领域或快照而交接基线丢失时拒绝重新初始化，不能悄悄回到初始产物。首次创建状态目录时同步目录链，覆盖新增父目录的持久化边界。

部署清单严格限定 `initial_release` 与 `policy`。移除 CLI host/worker 角色、infrastructure 和 --update-host；旧内部包暂保留作回归基础，不在默认运行路径。控制 UDS 同时检查 peer UID 与管理凭据，普通公共管理 Token 不授予执行产物的权限。候选继承本轮只读 YAML 和已校验 listener，不在命令行暴露凭据。

## 交接与恢复

共享、entry、release 状态在同一个封存点捕获，包含会话与公开资源/Agent 归属、配置/数据幂等、活动租约、回执与淘汰边界、分页缓存、分配与结果证据、发布报告。快照及目录先同步，再持久化 SEALED；源关闭领域 writer 后最后释放 owner.lock。候选取得锁并重读决定，再导入和持久 COMMITTED。COMMITTED 后禁止旧 owner 回退或停止新版。

预览检查点与最终提交屏障分离。只在预览捕获时暂停候选状态/分配调用，捕获后立刻恢复，再传输和校验；避免把大镜像传输全部计入默认 2 秒状态等待。回归测试在 Transfer 内故意阻塞快照 ACK，确认候选真实请求仍能成功且只执行一次。 随后竞态回归还复现了最终屏障因入口记录反复 JSON 复制而超过等待预算的问题；入口镜像改为复制值类型 Map 和独立的候选指针，并验证导出/导入镜像与两个运行时均无可变别名。入口复制优化后重复验证仍出现超时，随后提交路径复用已验证的最终只读镜像，取得写锁后仍核对持久决定和完整快照字节；可写状态继续独立重建。拒绝缓存决定或内容不匹配，预览镜像不能用于提交。保持 2 秒等待预算。

增量为两个一致检查点间的字节差量，绑定 epoch、logical_revision、SHA-256 和大小。接收端检查精确基线、范围、revision 和预算，再重建完整只读镜像并验证业务不变量。基线缺口、摘要错误或超限拒绝该次交接，不静默扩大预算。预览 ACK 不授予让锁或提交权；最终仍要求精确 SEALED 镜像。

准备期限覆盖整个追赶过程；最终屏障覆盖捕获、传输、验证和提交；激活另有期限。等待队列同时约束条数、序列化字节和原 deadline。临时收紧传输预算不覆盖接管后的长期 Policy。候选上的活动 SSE 可以携租约跨提交结束，不重放上游请求；旧版执行和转发中的长流必须先排空。

提交/激活回执丢失时核对持久决定、实际身份与写锁，通过私有恢复端点继续。提交前通道 EOF 使候选退出，提交后不因旧父退出而杀死新版。恢复通知失败保留候选记录并阻止第三实例；只有确认退出且租约清理完成才能替换。

COMPLETED 还要求新版状态和控制独立可用、MainPID/READY 确认、源实际退出和配置解冻。冷启动恢复当前业务日志，不用旧快照覆盖新版提交后新增的数据。源恢复与候选提交争同一把锁，只有一方成功。

## 已执行验证

macOS arm64 / Go 1.24.4：全量 Go 测试、竞态、vet；真实候选子进程覆盖活动 SSE、基线差量、回执丢失、源恢复、第三实例拒绝和队列预算。详细持久化回归见 [验证记录](../VALIDATION.md)：日志写入/fsync、12 个快照故障点、7 条决定转换截断、14 组日志压缩故障和 8 个真实压缩 SIGKILL 点。

`deploy/rollout-process/complete.py` 使用三个不同摘要的实际产物与模拟上游，覆盖自动 A→B→C、旧流排空、新流跨提交、失败回退、排空超时和 resume、提交后拒绝回退、无样本自动回退与冷启动恢复。最终修复后的竞态构建连续三轮通过。`deploy/rollout-local/check.py` 现在转发到该完整进程脚本。

`deploy/rollout-systemd/process.py --reuse-image --cycles 20` 在无宿主挂载/公开端口的独立 Debian 容器中执行真实安装器，通过：

- 非 root、LoadCredential、Type=notify、NotifyAccess=main、KillMode=mixed、一个稳定服务 PID。
- A→B→C、旧 SSE 排空、新版入口/状态/控制接管、MainPID 正确，正常升级没有 systemd 重启。
- 真正安装 CLI 在 VERIFYING 退出，任务继续并允许重连复用。
- 失败候选回退，之后可重新成功发布；主进程 SIGKILL 后恢复已提交产物及业务状态。
- 双进程期间 stop 清理服务组；提交前 start 保留原稳定版本；卸载后保留凭据/业务状态/决定并重装。
- 容器重启按持久决定选择已提交版本；额外连续发布 20 轮，采样到的服务网关进程最多两个。

## 实际 Agent 验收状态

`deploy/rollout-process/agent.py` 创建两个独立 Hermes 容器、全新凭据/数据和临时网关，不改动既有部署。使用本机已有模型配置，没有替换模型。报告默认 `/tmp/gateway-real-agent-rollout.json`，只有完整过程成功才写 passed=true。

本轮通过发布前真实 HTTP/SSE 的会话及记忆续接，以及 A2A 同步/流式任务、context、列表分页、查询和调用方隔离。候选验证阶段模型服务持续返回过载错误，停止该次测试并清理临时容器。报告为 passed=false，记录中断类型；不能据发布前基线宣布实际 Agent 换版通过。另一次运行出现上游 completed task 无文本，也未计为成功。最新重试在发布前报告 Native session SSE reported failure，报告 `/tmp/gateway-real-agent-rollout-final.json` 同样为 passed=false；未根据此前过载现象推断这次错误的具体原因。

## 后续工作

1. 按 logical_revision 连续记录操作增量，减少检查点全量捕获/解码/重建开销；保持无上游副作用及预算边界。
2. 补齐完整网关各提交位置的 SIGKILL、目录创建故障和目标文件系统/存储同步矩阵。现有测试不等于物理断电验证。
3. 模型服务恢复后完成四 profile 的实际 Agent 换版、失败回退后再成功发布，并核对存量资源与 Agent 归属。
4. 目标负载下测量并发、CPU、精确屏障停顿、增量和排空时长，覆盖容量边缘和长时间连续发布，再据结果调整预算。

当前默认 install 已接线，尚未达到实施方案“所有阶段完成”的整体放行标准。产物与快照采用保守的全部保留策略，SIGKILL 遗留临时文件不参与恢复；自动清理需另行实现并证明不会删除活动恢复依据。
